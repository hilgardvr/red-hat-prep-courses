# Lab kit

Two disposable RHEL 10-family virtual machines for the RHCSA Field Guide.

| Machine | Address | Resources | Role |
|---|---|---|---|
| `server` | `10.10.10.10` | 2 vCPU, 4 GB RAM, 20 GB root + 10 GB `/dev/vdb` | Main practice system |
| `node2` | `10.10.10.11` | 1 vCPU, 2 GB RAM, 20 GB root | SSH, NFS, firewall, and client/server target |

Both machines run AlmaLinux 10, a free RHEL 10-compatible rebuild that needs no subscription. The course targets RHEL 10 for the exam and calls out rebuild differences where they matter.

## Quick start

```bash
./bin/lab doctor          # check host dependencies
./bin/lab up              # create and provision both VMs
./bin/lab snapshot clean  # save a clean state
./bin/lab ssh             # log in to server as vagrant
```

Lab accounts:

| User | Password | Notes |
|---|---|---|
| `vagrant` | `vagrant` | Passwordless sudo, used by provisioning |
| `labuser` | `labpass` | Member of `wheel`; normal sudo with password |

The labs use `labuser`. Switch to it after login:

```bash
sudo su - labuser
```

## Commands

| Command | Effect |
|---|---|
| `./bin/lab doctor` | Check Vagrant, libvirt, KVM, RAM, disk, and the lab key |
| `./bin/lab up` | Create or start both VMs |
| `./bin/lab status` | Show VM status |
| `./bin/lab ssh [server\|node2]` | Log in (default `server`) |
| `./bin/lab snapshot [name]` | Snapshot both VMs (default `clean`) |
| `./bin/lab restore [name]` | Restore both VMs (default `clean`) |
| `./bin/lab check r01 lab1` | Run a lab checker |
| `./bin/lab halt` | Shut down both VMs |
| `./bin/lab reset` | Destroy and rebuild both VMs |
| `./bin/lab destroy` | Delete both VMs (asks for confirmation) |

## Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `LAB_KEY_PATH` | `keys/lab_ed25519` | Lab SSH private key (generated by `./bin/lab up`) |

The lab installs its base packages from the box's own online repositories, so the host and both VMs need internet access on first boot.

## How provisioning works

On first boot, `provision/common.sh`:

1. Sets the hostname and writes both lab hosts to `/etc/hosts`.
2. Configures the private NIC with a NetworkManager profile named `lab-private`, applying `10.10.10.10` or `10.10.10.11`.
3. Installs base packages, including `man`, `vim`, `tar`, `gzip`, `bzip2`, and `firewalld`.
4. Enables `firewalld`, then asserts that SELinux is enforcing and that the firewall is active and enabled.
5. Creates `labuser` with password `labpass` and membership in `wheel`.
6. Installs the shared lab SSH key for `vagrant` and `labuser`.
7. Writes `~/.ssh/config` entries for `server` and `node2`, so cross-VM `ssh` and `scp` work without flags.

The Vagrantfile attaches both VMs to the libvirt network `rhcsa-lab` with DHCP disabled. It also forces `qemu_use_session = false`, because vagrant-libvirt 0.11.x otherwise defaults to the session connection, where private networks cannot be created.

`provision/node2.sh` enables `sshd` and creates `/home/labuser/handoff`.

## Checkers

Checkers live in `checks/<module>/check.sh` and run inside `server` as root. The `lab check` wrapper uploads the script and executes it:

```bash
./bin/lab check r01 lab1
./bin/lab check r02 lab1
./bin/lab check r02 challenge
./bin/lab check r02 all
```

`all` assumes the end states of every lab in that module are present at the same time. If you restored the clean snapshot between labs, check them individually.

Checkers inspect the end state, not the commands used. They include a reboot-persistence task where the module requires it.

## Troubleshooting

- **`vagrant` missing:** install Vagrant and then `vagrant plugin install vagrant-libvirt`.
- **KVM permission denied:** add your user to the `libvirt` and `kvm` groups, then log out and back in.
- **`Network 10.10.10.10 is not available`:** older vagrant-libvirt releases default to the session connection, which cannot create private networks. The Vagrantfile sets `qemu_use_session = false`; destroy and rebuild with `./bin/lab destroy && ./bin/lab up`. Confirm `virsh --connect qemu:///system net-list --all` shows `rhcsa-lab`.
- **Private IP missing or DHCP-assigned:** inside the VM, run `ip -4 addr show eth1` and `nmcli connection up lab-private`. If the profile is absent, rebuild with `./bin/lab reset`.
- **Box download fails:** check network/proxy settings; pre-fetch with `vagrant box add almalinux/10 --provider libvirt`.
- **`dnf` fails during provisioning:** the VM could not reach the AlmaLinux repositories. Check the host's network and proxy settings, then rebuild with `./bin/lab destroy && ./bin/lab up`.
- **Cross-VM SSH fails:** confirm both VMs are running (`./bin/lab status`) and that `~/.ssh/lab_ed25519` exists on both.

## Security

The lab is disposable and uses well-known passwords. It is not hardened and must not be exposed to an untrusted network. Destroy it when you are finished.
