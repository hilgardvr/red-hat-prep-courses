# R9 cheat sheet

A compact reference for review. Everything here is explained in the [theory page](index.md).

## Three objects

| Object | What it is | Shown by |
|---|---|---|
| Device | Kernel interface | `nmcli device status` |
| Connection | Saved profile (a file) | `nmcli connection show` |
| Active connection | Profile applied to a device | `nmcli connection show --active` |

Profiles live in `/etc/NetworkManager/system-connections/*.nmconnection`, mode `0600`.

## nmcli

```bash
nmcli device status
nmcli connection show
nmcli connection show --active
nmcli connection show lab0
nmcli connection add type dummy ifname lab0 con-name lab0 \
  ipv4.method manual ipv4.addresses 192.0.2.10/24 \
  ipv4.dns 192.0.2.53 ipv4.dns-search r9.lab \
  ipv6.method manual ipv6.addresses 2001:db8::10/64
nmcli connection modify lab0 ipv4.never-default yes ipv6.never-default yes
nmcli connection up lab0
nmcli connection down lab0
nmcli connection delete lab0
nmcli connection reload
nmcli device reapply lab0
```

| Property | Meaning |
|---|---|
| `ipv4.method manual` | Use the profile's addresses |
| `ipv4.method auto` | DHCP |
| `ipv4.method disabled` | No IPv4 on this profile |
| `ipv4.addresses 192.0.2.10/24` | Comma-separated list |
| `ipv4.gateway 192.0.2.1` | Default gateway |
| `ipv4.dns 192.0.2.53` | DNS servers |
| `ipv4.dns-search r9.lab` | Search domain |
| `ipv4.never-default yes` | Never install a default route |
| `connection.autoconnect yes` | Activate at boot |

`modify` writes the file; it does **not** apply. Follow it with `connection up` or `device reapply`.

## Addresses and routes

```bash
ip -brief addr
ip addr show lab0
ip route
ip -6 route
ss -ltn
ss -lun
ping -c2 192.0.2.10
ping -6 -c2 2001:db8::10
```

| | IPv4 | IPv6 |
|---|---|---|
| Loopback | `127.0.0.1` | `::1` |
| Documentation range | `192.0.2.0/24` | `2001:db8::/32` |
| Link-local | `169.254.0.0/16` | `fe80::/10` |
| Normal LAN prefix | `/24` | `/64` |

`ip addr add` and `ip route add` change the running kernel only. They do not survive a reboot.

`nmcli -g` terse output escapes IPv6 colons as `\:` — `2001\:db8\:\:10/64`. Strip the backslashes or read `ip addr`.

## Name resolution

```text { .no-copy }
# /etc/nsswitch.conf
hosts:      files myhostname dns
```

| Source | Reads |
|---|---|
| `files` | `/etc/hosts` |
| `myhostname` | The machine's own name and addresses |
| `dns` | Nameservers from `/etc/resolv.conf` |

```text { .no-copy }
192.0.2.11   r9peer.r9.lab r9peer
10.10.10.10  server.r9.lab
```

```bash
getent hosts r9peer          # every address, every name
getent ahostsv4 r9peer       # IPv4 only, one line per address
getent ahostsv6 r9peer
```

| Task | Command |
|---|---|
| Set DNS | `nmcli connection modify lab0 ipv4.dns 192.0.2.53` |
| Set search domain | `nmcli connection modify lab0 ipv4.dns-search r9.lab` |
| Prefer this profile's DNS | `nmcli connection modify lab0 ipv4.dns-priority -50` |
| Read the result | `cat /etc/resolv.conf` |

`/etc/resolv.conf` is generated by NetworkManager. Editing it by hand lasts until the next reconnect.

## Hostname

```bash
hostnamectl
hostnamectl set-hostname server.r9.lab
hostnamectl --static
hostnamectl --transient
```

| Kind | Stored in | Survives reboot |
|---|---|---|
| Static | `/etc/hostname` | Yes |
| Transient | Kernel | No |
| Pretty | `/etc/machine-info` | Yes |

`set-hostname` does not touch `/etc/hosts`. Add the mapping yourself.

## firewalld

```bash
firewall-cmd --get-default-zone
firewall-cmd --get-active-zones
firewall-cmd --list-all
firewall-cmd --list-all-zones
firewall-cmd --permanent --get-zones
```

| Field in `--list-all` | Meaning |
|---|---|
| `target` | What happens to traffic the zone does not allow |
| `interfaces` | Interfaces assigned to the zone |
| `sources` | Source networks assigned to the zone |
| `services` | Named services from `/usr/lib/firewalld/services/` |
| `ports` | Raw `port/protocol` openings |
| `rich rules` | Rules with addresses, logging, rate limits |

Zone selection is by **incoming interface** or **source address**. Whatever is left goes to the default zone.

## Services and ports

```bash
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --permanent --remove-port=8080/tcp
firewall-cmd --zone=public --query-port=8080/tcp
firewall-cmd --zone=public --list-services
firewall-cmd --zone=public --list-ports
```

| Service | Ports |
|---|---|
| `ssh` | 22/tcp |
| `http` | 80/tcp |
| `https` | 443/tcp |
| `nfs` | 2049/tcp plus related |
| `ntp` | 123/udp |

Prefer a service when one exists: it carries its auxiliary ports, which a bare number does not.

## Runtime versus permanent

| Layer | Lives in | Survives reload | Survives reboot |
|---|---|---|---|
| Runtime | Running nftables rules | No | No |
| Permanent | `/etc/firewalld/zones/*.xml` | After `--reload` | Yes |

```bash
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --reload
firewall-cmd --list-ports
```

| Command | Effect |
|---|---|
| `firewall-cmd --reload` | Discard runtime rules, apply permanent files |
| `firewall-cmd --runtime-to-permanent` | Save the running rules to disk |
| `firewall-cmd --complete-reload` | Full restart of the firewall |

## Zones for an interface

```bash
firewall-cmd --permanent --new-zone=r9web
firewall-cmd --permanent --zone=r9web --add-service=http
firewall-cmd --permanent --zone=r9web --add-port=8080/tcp
firewall-cmd --permanent --zone=r9web --add-interface=lab0
firewall-cmd --reload
```

```text { .no-copy }
The interface is under control of NetworkManager, setting zone to 'r9web'.
```

That message means firewalld stored the assignment in the connection profile as `connection.zone=r9web`, which is what makes it survive a reboot.

```bash
firewall-cmd --permanent --zone=r9web --remove-interface=lab0
firewall-cmd --permanent --delete-zone=r9web
firewall-cmd --reload
```

A zone must be empty before it can be deleted.

## Verifying

```bash
ss -ltn
curl -fsS --max-time 5 http://10.10.10.10:8080/
ssh labuser@node2 "curl -fsS --max-time 5 http://10.10.10.10:8080/"
```

| Result | Means |
|---|---|
| `Could not connect` / `Connection refused` | No rule for that port in the zone the traffic enters, or nothing listening |
| Timeout | Packets dropped, or the address is wrong |
| The page | The listener, the zone, and the route are all correct |

`curl http://127.0.0.1:8080/` proves nothing about the firewall: loopback does not traverse the interface rules.

## Traps

| Trap | Fix |
|---|---|
| `modify` with no `up` | `nmcli connection up <name>` |
| `ip addr add` for an exam task | Put it in a profile |
| No `autoconnect yes` | Address is gone after reboot |
| A second gateway | `never-default yes` |
| Editing `/etc/resolv.conf` | Set DNS on the profile |
| `--add-port` without `--permanent` | Lost at the next reload |
| `--permanent` without `--reload` | Looks broken until reboot |
| Opening `http`, testing `8080` | Services and ports are different lists |
| Rule in the wrong zone | Match the zone of the incoming interface |
| Removing `ssh` from the active zone | Your session dies; use the console |
| `hostnamectl` alone | Add the `/etc/hosts` line |
| Testing with `curl` to loopback | Test from `node2` |
